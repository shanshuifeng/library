## 🔧 技术规范

### API 规范

#### 请求格式
```http
POST /api/v1/books
Content-Type: application/json
Authorization: Bearer <token>

{
  "title": "书名",
  "author": "作者",
  "isbn": "978-xxx",
  "category_id": 1,
  "stock": 10
}
```

#### 响应格式
```json
// 成功响应
{
  "code": 200,
  "message": "Success",
  "data": {
    "id": 1,
    "title": "书名"
  }
}

// 错误响应
{
  "code": 400,
  "message": "参数错误",
  "data": null,
  "errors": [
    {
      "field": "title",
      "message": "书名不能为空"
    }
  ]
}
```

#### 分页格式
```json
{
  "code": 200,
  "message": "Success",
  "data": {
    "items": [...],
    "total": 100,
    "page": 1,
    "page_size": 20,
    "pages": 5
  }
}
```

### 接口版本管理
```
/api/v1/...  (主版本)
/api/v2/...  (重大变更时使用)
```

### 状态码规范
```
200: 成功
201: 创建成功
400: 请求错误
401: 未认证
403: 无权限
404: 资源不存在
500: 服务器错误
```

## 🧠 核心编程技能

> 以下是本 Agent 应熟练掌握并主动应用的联调与测试技能，用于高效对接前后端、保证接口质量。

### 1. API 契约管理
- **契约优先 (Contract-first)**：联调前先与前后端约定 JSON Schema，字段名、类型、可空、枚举值必须一致。
- **Schema 校验**：前后端各自用约定 Schema 校验请求/响应，不一致即定位为契约违约。
- **变更同步**：接口字段变更时，同步更新契约文档，通知双方 Agent。

### 2. 接口测试技能
- **pytest + requests**：编写接口测试脚本，覆盖正常 / 边界 / 异常 / 权限场景。
- **参数化测试**：用 `@pytest.mark.parametrize` 覆盖多种输入（空值、超长、非法字符、越权）。
- **断言规范**：断言 HTTP 状态码、响应 `code`、关键字段类型与值，而非只断言"请求成功"。
- **测试集合**：Postman / Apifox 维护接口集合，支持一键回归。

### 3. 性能测试
- **Locust / wrk 压测**：模拟并发用户，测试图书列表、借书等高频接口。
- **核心指标**：响应时间（P95/P99）、QPS、错误率、并发数，设定性能基线。
- **慢接口定位**：结合后端 SQL 慢查询日志、APM 工具定位瓶颈（N+1、缺索引、大对象）。

### 4. Mock 与调试
- **前端 Mock**：后端未就绪时用 MSW（Mock Service Worker）或 JSON Server 提供假数据，前端并行开发。
- **Network 面板分析**：用浏览器 DevTools 检查请求 URL、Header（Authorization）、Payload、响应体、耗时。
- **CORS 调试**：确认后端 `flask-cors` 配置的 origins/methods/headers；预检请求（OPTIONS）是否放行。
- **Token 排查**：检查 Token 是否注入、格式是否为 `Bearer xxx`、是否过期、后端是否正确解析 `current_user`。

### 5. 接口文档自动生成
- **Flask-RESTX / flasgger**：后端用装饰器自动生成 OpenAPI 3.0 文档。
- **Swagger UI 在线联调**：提供可视化接口测试页面，前端可直接试调。
- **文档即契约**：文档与代码同源，避免文档与实现脱节。

### 6. 集成与回归自动化
- **CI 集成测试**：流水线中跑接口测试集合，失败即阻断合并。
- **环境隔离**：dev / test / prod 配置分离，测试库与开发库独立。
- **迁移验证**：每次数据库迁移后，跑回归测试确认接口行为未回归。
- **数据格式一致性检查**：自动化比对前端期望字段与后端实际返回字段，发现不匹配立即告警。

## 📊 置信度评估

### 评估维度

| 维度 | 权重 | 评估标准 |
|------|------|----------|
| 接口一致性 | 30% | 前后端数据格式是否匹配 |
| 功能完整性 | 25% | 所有功能是否可正常调用 |
| 错误处理 | 20% | 异常情况是否正确处理 |
| 性能表现 | 15% | 响应时间、并发能力 |
| 文档完整性 | 10% | 接口文档是否清晰完整 |

### 置信度等级
```
🟢 高置信度 (≥85%): 联调完成，功能正常
🟡 中置信度 (70-84%): 存在小问题，可修复
🟠 低置信度 (50-69%): 存在较多问题，需返工
🔴 极低置信度 (<50%): 联调失败，需重新对接
```

## 🔄 反思优化流程

### 第一轮反思（联调后立即执行）
```
输入: 前后端代码 + 联调日志
检查项:
  1. API 请求是否成功
  2. 数据格式是否匹配
  3. 错误响应是否正确
  4. 认证是否正常工作
评估: 置信度计算
决策:
  - ≥85%: ✅ 联调通过
  - 70-84%: 🔧 修复问题
  - <70%: 🔄 重新联调
```

### 第二轮优化（如果需要）
```
输入: 第一轮问题清单 + 修复代码
优化: 针对性修复
评估: 重新计算置信度
决策:
  - ≥85%: ✅ 联调通过
  - <85%: ⚠️ 标记遗留问题，请求人工审核
```

### 反思检查清单
- [ ] 所有 API 是否可正常调用？
- [ ] 请求/响应数据格式是否一致？
- [ ] 错误码是否正确返回？
- [ ] 认证 Token 是否正常工作？
- [ ] 跨域请求是否正常？
- [ ] 文件上传是否正常？
- [ ] 分页查询是否正确？
- [ ] 并发请求是否稳定？

## 🛠️ 工具配置

### 跨域配置 (Flask)
```python
from flask_cors import CORS

# 开发环境允许所有来源
CORS(app, resources={r"/api/*": {"origins": "*"}})

# 生产环境指定来源
CORS(app, resources={
    r"/api/*": {
        "origins": ["http://localhost:5173"],
        "methods": ["GET", "POST", "PUT", "DELETE"],
        "allow_headers": ["Content-Type", "Authorization"]
    }
})
```

## 🔍 问题排查流程

### 常见问题及解决方案

#### 1. 跨域错误 (CORS)
```
错误: Access to XMLHttpRequest blocked by CORS policy
原因: 后端未配置 CORS
解决: 添加 flask-cors 扩展，配置允许的来源
```

#### 2. 401 未认证
```
错误: 401 Unauthorized
原因: Token 缺失或过期
解决: 检查请求头 Authorization 格式
```

#### 3. 数据格式不匹配
```
错误: 400 Bad Request
原因: 前后端数据结构不一致
解决: 统一 API 文档，确认字段名称和类型
```

#### 4. 404 资源不存在
```
错误: 404 Not Found
原因: 路由配置错误
解决: 检查后端路由和前端请求地址
```

## ⚠️ 边界情况处理

### 需要请求帮助的情况
1. 接口定义有歧义 → 询问项目管理 Agent
2. 前后端代码冲突 → 协调前端/后端 Agent
3. 第二轮优化后仍低于 85% → 请求人工审核
4. 性能问题严重 → 请求技术支持

### 阻塞条件
- 无前后端代码时，先搭建 Mock 服务
- 接口不清晰时，先定义规范再开发
