## 🧠 核心编程技能

> 以下是本 Agent 应熟练掌握并主动应用的编程技能，用于在生成代码时提升质量、性能与可维护性。

### 1. 组件设计与复用
- **组合式函数 (Composables)**：将可复用逻辑（如分页、表单、权限）抽取为 `useXxx()`，跨组件共享状态与逻辑。
- **插槽 (Slots)**：默认 / 具名 / 作用域插槽，实现组件内容可定制化，避免过度通过 Props 传递节点。
- **原子设计**：基础组件（原子）→ 业务组件（分子）→ 页面（模板），保持组件职责单一。
- **Props 设计**：遵循单向数据流，子组件通过 `defineEmits` 通知父组件，避免直接修改 Props。

### 2. 性能优化
- **路由懒加载**：`() => import('@/views/xxx.vue')` 按需加载，减小首屏体积。
- **虚拟列表**：图书列表/借阅记录数据量大时，使用 `vue-virtual-scroller` 仅渲染可视区域。
- **防抖 / 节流**：搜索框输入用 `lodash.debounce`（如 300ms），避免频繁请求。
- **v-show vs v-if**：频繁切换用 `v-show`，条件渲染用 `v-if`。
- **列表 key**：使用稳定唯一值（如 `book.id`），禁止用数组 index 作为 key。
- **Keep-alive**：缓存列表页状态，从详情页返回时保留滚动位置与筛选条件。
- **图片优化**：懒加载（`loading="lazy"`）+ 压缩缩略图 + 占位骨架屏。

### 3. 状态管理 (Pinia)
- **模块化 Store**：按领域拆分 `useUserStore` / `useBookStore` / `useBorrowStore`。
- **Getters**：派生计算（如"当前借阅数量"、"是否达到借阅上限"）放 getters，避免组件内重复计算。
- **持久化**：用户登录态、Token 用 `pinia-plugin-persistedstate` 持久化到 localStorage。
- **Action 处理异步**：API 调用集中在 action，组件只触发不直接请求。

### 4. 表单与校验
- **Element Plus 表单校验**：`el-form` + `rules` 定义校验规则（required / pattern / min-max）。
- **自定义校验器**：ISBN 格式、密码强度、借阅数量上限等用自定义 `validator`。
- **动态表单**：分类级联、批量导入等动态渲染表单项。
- **防重复提交**：提交按钮 loading 状态 + 防抖，防止用户多次点击。

### 5. HTTP 请求封装
- **拦截器**：请求拦截注入 `Authorization` Token；响应拦截统一处理 `code` 与错误提示。
- **请求取消**：页面切换或重复搜索时用 `AbortController` 取消未完成请求。
- **统一错误处理**：401 自动跳转登录、Token 过期自动刷新、网络异常友好提示。
- **文件上传/下载**：FormData 上传封面图，Blob + `a.download` 实现导出。

### 6. 代码质量与可访问性
- **ESLint + Prettier**：统一代码风格，提交前自动修复。
- **语义化标签**：使用 `<header>/<nav>/<main>/<section>`，提升可访问性与 SEO。
- **TypeScript 友好**：关键接口定义类型（API 响应、Store 状态），增强可维护性。
- **中文注释**：复杂逻辑、业务规则必须注释，组件 Props/Emits 用 JSDoc 标注。

## 📊 置信度评估

### 评估维度

| 维度 | 权重 | 评估标准 |
|------|------|----------|
| 功能完整性 | 30% | 是否覆盖所有需求功能点 |
| 代码质量 | 25% | 命名规范、注释、结构清晰度 |
| 用户体验 | 20% | 交互流畅度、响应式适配 |
| 性能优化 | 15% | 加载速度、渲染性能 |
| 兼容性 | 10% | 浏览器兼容、移动端适配 |

### 置信度等级
```
🟢 高置信度 (≥85%): 代码可直接使用，无需修改
🟡 中置信度 (70-84%): 需要小幅调整
🟠 低置信度 (50-69%): 需要重构部分内容
🔴 极低置信度 (<50%): 需要重新开发
```

## 🔄 反思优化流程

### 第一轮反思（生成后立即执行）
```
输入: 生成的代码
评估: 置信度计算
决策:
  - ≥85%: ✅ 提交代码
  - 70-84%: 🔧 进入优化
  - <70%: 🔄 重新生成
```

### 第二轮优化（如果需要）
```
输入: 第一轮代码 + 问题清单
优化: 针对性修复
评估: 重新计算置信度
决策:
  - ≥85%: ✅ 提交代码
  - <85%: ⚠️ 标记问题，请求人工审核
```

- [ ] 所有组件是否正确注册？
