# 大学图书管理系统 - 开发工作流

## 📋 工作流概述

本工作流协调 4 个 Agent 协作完成大学图书管理系统的开发：
- **前端 Agent**: Vue 3 + Element Plus 前端开发
- **后端 Agent**: Flask + MySQL 后端开发
- **联调 Agent**: 前后端对接与集成测试
- **项目管理 Agent**: 代码审核与质量把控

---

#### 业务规则
```
1. 借书规则:
   - 学生最多借 5 本
   - 教师最多借 10 本
   - 借期 30 天
   - 库存 > 0 才能借

2. 续借规则:
   - 最多续借 2 次
   - 每次续借 15 天
   - 有逾期未还不能续借

3. 还书规则:
   - 逾期每天罚款 0.1 元
   - 还书时计算罚款
   - 还书后更新库存

4. 罚款规则:
   - 逾期罚款 = 逾期天数 × 0.1
   - 罚款未缴不能借书
```

## 🔁 反思优化机制

### 通用反思流程
```
┌─────────────────────────────────────────────────────────────┐
│                    Agent 生成代码                           │
└──────────────┬──────────────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────────────┐
│               第一轮反思 (立即执行)                          │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  1. 按检查清单逐项检查                              │    │
│  │  2. 计算置信度                                      │    │
│  │  3. 决策: 通过 / 优化 / 重新生成                    │    │
│  └─────────────────────────────────────────────────────┘    │
└──────────────┬──────────────────────────────────────────────┘
               │
               ▼ (如果需要优化)
┌─────────────────────────────────────────────────────────────┐
│               第二轮优化                                    │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  1. 针对性修复问题                                  │    │
│  │  2. 重新评估置信度                                  │    │
│  │  3. 决策: 通过 / 请求人工审核                       │    │
│  └─────────────────────────────────────────────────────┘    │
└──────────────┬──────────────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────────────┐
│               PM Agent 审核                                 │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  1. 代码质量检查                                    │    │
│  │  2. 功能验收                                        │    │
│  │  3. 最终决策: 通过 / 返工 / 人工干预                │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 置信度阈值
| 阈值 | 决策 | 后续行动 |
|------|------|----------|
| ≥85% | ✅ 通过 | 提交代码，进入下一阶段 |
| 70-84% | 🔧 优化 | 进入第二轮优化 |
| 50-69% | ⚠️ 人工审核 | 请求 PM Agent 审核 |
| <50% | 🔄 重新开发 | 重新生成代码 |

## 🚨 异常处理

### Agent 失败处理
```
1. Agent 超时
   ├─ 通知 PM Agent
   ├─ PM Agent 评估是否需要人工干预
   └─ 重新分配任务或请求帮助

2. Agent 置信度过低
   ├─ Agent 自动请求帮助
   ├─ PM Agent 评估问题
   └─ 决策: 人工干预 / 重新开发

3. 前后端冲突
   ├─ 联调 Agent 协调
   ├─ 必要时 PM Agent 介入
   └─ 统一接口规范
```

### 人工干预触发条件
```
1. 置信度 < 70% 且无法优化
2. 关键功能无法实现
3. 安全漏洞无法修复
4. 进度严重滞后（>2天）
5. 技术方案有重大分歧
```
